01

Install on your VPS.

SSH into the computer you want your agent to use. Run:

VPS TERMINAL
curl -fsSL https://agentvps.ai-infra.org/install.sh -o install-agentvps.sh
sudo bash install-agentvps.sh

Installs version 0.0.1: the CLI, service, Chromium, and Linux desktop. The download is checked against a pinned SHA-256. Read the installer ↗

02

Open your computer.

Allow TCP 8080 in your VPS firewall, then open http://YOUR_VPS_IP:8080. Retrieve your access token locally and paste it into the login screen:

VPS TERMINAL
sudo cat /var/lib/agentvps/token

Keep this token private. Public IP access uses HTTP; use HTTPS or SSH forwarding for private work. Port 8081 is optional for sharing web previews.

03

Connect your agent.

On the computer running your agent, install the client with Node.js 22 or newer:

AGENT’S COMPUTER
npm install -g https://github.com/agentsdance/agentvps/releases/download/v0.0.1/agentsdance-agentvps-0.0.1.tgz

Copy the token over SSH, then connect. Replace ubuntu with your SSH username if different:

AGENT’S COMPUTER
mkdir -p ~/.config/agentvps
umask 077
ssh ubuntu@YOUR_VPS_IP 'sudo cat /var/lib/agentvps/token' > ~/.config/agentvps/vps.token
agentvps connect --url http://YOUR_VPS_IP:8080 --token-file ~/.config/agentvps/vps.token
agentvps status
codex mcp add agentvps -- agentvps mcp

The last line registers Codex. For Claude Code or another MCP client, use command agentvps with arguments ["mcp"]. See the connection config ↓

Complete CLI reference ↗
01 / CHECK

Know it’s ready.

VPS
sudo agentvps status
sudo agentvps call health_check '{"browser":true}'

Check the workspace identity and each capability. A running service alone doesn’t prove the browser or desktop works.

02 / UPGRADE

Keep your files.

Download the next release package, then run:

VPS
sudo agentvps upgrade ./agentsdance-agentvps-VERSION.tgz

Files, browser profile and configuration stay. Live commands and app windows close during the restart. For an early unscoped installation, rerun the installer to migrate first.

03 / UNINSTALL

Leave on your terms.

VPS
agentvps uninstall --dry-run
sudo agentvps uninstall

Your data stays by default. Add --purge only to permanently delete the workspace and credentials.

GOOD TO KNOW

A few details.

Is this already an autonomous personal agent?

Version 0.0.1 supplies the remote computer and tool layer. Bring Codex, Claude Code, or another agent to operate it. Built-in conversations and a model-driven agent loop are planned.

Can I watch everything my agent does?

Browser and native desktop actions appear live on the desktop. Background shell jobs appear in Commands, and API terminal sessions appear in Remote desk. Ask your agent to use a native terminal when you want to watch commands being typed.

What happens when I take over?

Your mouse and keyboard control the desktop. New agent browser and desktop mutations are blocked until you return control. Background jobs and actions already in progress continue.

What survives a restart?

Workspace files, notes, schedules, finished job receipts and the Chromium profile persist. Live commands, terminal sessions, app windows and preview links do not. Disconnecting the viewer alone leaves the remote apps running.

Is this isolated from the rest of my VPS?

AgentVPS runs as one unprivileged Linux user. It is a single-owner computer, not a multi-tenant sandbox. Commands have that OS user’s permissions. Authentication is required for tools and desktop access.

Something didn’t start. Where do I look?

Run sudo systemctl status agentvps and sudo journalctl -u agentvps -n 50. Check cloud firewall access to port 8080, then run the health check above. Report an issue with version and error details, without your token.
